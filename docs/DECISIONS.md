# Implementation decisions

ADR-style log of choices made while implementing [`PRD.md`](../PRD.md). Newest last.
Format: date · context · decision · consequences.

## D-001 · 2026-11-17 · Toolchain versions

- **Context:** The newest TypeScript (7.x) isn't supported by typescript-eslint yet (it requires
  `<6.1`). ESLint 9 is out of support, and `eslint-plugin-jsx-a11y` doesn't support ESLint 10.
  `@cloudflare/vitest-pool-workers` was renamed to `@cloudflare/vitest-plugin`.
- **Decision:** TypeScript `~6.0`, ESLint 10 with `eslint-plugin-jsx-a11y-x` (the maintained fork
  with ESLint 10 support), Vitest 5, `@cloudflare/vitest-plugin` (its `cloudflareTest()` Vite
  plugin; tests call the Worker through `exports.default.fetch` from `cloudflare:workers`).
- **Consequences:** Move to TypeScript 7 once typescript-eslint supports it.

## D-002 · 2026-11-17 · pnpm 12 supply-chain settings

- **Context:** pnpm 12 refuses packages published very recently (minimum release age) and blocks
  install scripts by default.
- **Decision:** Keep the default release-age protection. Instead of adding exceptions, version
  ranges allow slightly older releases. Only `esbuild` and `workerd` may run install scripts
  (`allowBuilds` in `pnpm-workspace.yaml`).
- **Consequences:** New dependencies may resolve to a version a day or two older than "latest".

## D-003 · 2026-11-17 · Local development topology

- **Context:** PRD §10.3 keeps the SPA (`apps/web`) and the Worker (`apps/api`) separate; the
  production Worker serves `../web/dist` as static assets.
- **Decision:** `pnpm dev` runs Vite on port 5173 (proxying `/api` to 8787) and `wrangler dev` on
  port 8787 in parallel, rather than using `@cloudflare/vite-plugin`. `apps/api/scripts/ensure-assets-dir.mjs`
  creates `apps/web/dist` so wrangler can start before the first build.
- **Consequences:** `APP_URL` in development is `http://localhost:5173` (the browser origin).

## D-004 · 2026-11-17 · Workspace packages are consumed as TypeScript source

- **Decision:** `@myvocab/core` and `@myvocab/contracts` export `./src/index.ts` directly; Vite and
  wrangler (esbuild) compile them. No separate build step.

## D-005 · 2026-11-17 · Generated Worker types are committed

- **Decision:** `apps/api/worker-configuration.d.ts` is generated by `pnpm --filter @myvocab/api cf-typegen`
  (`wrangler types`) and committed, so CI can typecheck without running wrangler. Re-run it after
  changing `wrangler.jsonc`.

## D-006 · 2026-11-17 · Fonts and button text color

- **Decision:** Only the Latin and Hebrew subsets of Rubik are bundled. Text on colored buttons
  uses `--on-color` (`#111014`): white text fails WCAG AA on the Know, Don't know and accent
  colors, dark text passes on all of them (≥ 4.5:1). Stop keeps light text.

## D-007 · 2026-11-17 · Scope of the no-vocabulary guard

- **Decision:** `check:no-vocabulary` checks tracked files plus untracked files that aren't
  git-ignored (so it also catches files about to be committed). Allow-listed: `seed/sample.csv`,
  `apps/api/migrations/*.sql` (schema only) and `**/fixtures/*.csv`; every allow-listed CSV is
  capped at 20 data rows.

## D-008 · 2026-11-17 · Loop engine details

- **Decision:** The loop state stores a seeded PRNG state (mulberry32), so `loopReducer` stays
  pure, tests are deterministic, and a loop restored from `sessionStorage` continues identically.
  The reducer works with item ids only; the UI looks up card content separately.
- **Undo:** the reducer keeps the most recent Know (`lastKnow`) until a new Know or Stop; the
  ~4-second Undo window is enforced by the UI timer. An undone card is appended to the next
  cycle's set; undoing after the last Know turns the summary back into a cycle break.
- **Order differs:** compared on the cards shared with the previous cycle (relative order); up to
  10 re-shuffles, then a rotation by one.

## D-009 · 2026-11-17 · CSV details

- **Decision:** Core has its own small RFC 4180 parser/serializer (no runtime dependency).
- Row numbers in import reports are spreadsheet lines (the header is line 1).
- "At least one translation or an explanation" is checked on the **merged** item (all rows of
  the same item in the file, plus the existing item), so a row may add only hints to an item
  defined elsewhere. Warnings (multiple meanings, mixed scripts) are also computed on the merged
  result, only for items the import creates or changes.
- `multiple_meanings` accepts `true/false`, `yes/no`, `1/0` (empty = false).
- List entries may not contain `|` (the CSV list separator, PRD §8.3); the shared item
  validation rejects it everywhere, which keeps the export round-trip exact.

## D-010 · 2026-11-17 · Database layer details

- **WITHOUT ROWID:** Drizzle 0.45 can't express it, so `migrations/0000_init.sql` was edited by hand
  for `item_categories`, `user_known_items` and `usage_counters`. `test/schema.test.ts` asserts it
  after all migrations run, so a future drizzle-kit table rebuild that drops it fails CI.
  When generating a new migration that rebuilds one of these tables, re-add `WITHOUT ROWID`.
- **Batches:** a D1 `batch()` counts as one query toward the per-invocation limit (50 on Free) and
  is one transaction. Drizzle's `db.batch()` can't hold raw SQL, so the import writer compiles every
  statement to `{ sql, params }` (still parameterized) and calls `D1Database.batch()` directly, up
  to 1,000 statements per batch.
- **Identity lookup:** existing items for an import are found with one query: the keys travel as
  a single JSON parameter (`json_each`) joined against `ux_items_identity`.
- **Concurrent edits during an import:** updates use the item `version`; an item that changed
  meanwhile is skipped and counted in `skippedConcurrent` (re-run the import to merge it).
- **Seeding:** `pnpm db:seed` applies local migrations, then runs the same `CsvImportService`
  through wrangler's `getPlatformProxy` (the local D1 that `wrangler dev` uses). `--remote` writes a
  temporary config with `remote: true` under `apps/api/.wrangler/tmp/` and asks for a typed
  confirmation; it needs the owner's `wrangler login`.
- **Languages** are seeded by migration `0001_seed_languages.sql` (data only).
- **Tests** reset storage and re-apply the migrations before every test.

## D-011 · 2026-11-17 · Learning experience (M3)

- **Order of guest checks in `POST /loops`:** validation → guests enabled / maintenance → Turnstile →
  hourly cap → selection → counter increment. Turnstile runs before the cap so an unverified request
  writes nothing at all (PRD §11.2 rule 5).
- **Turnstile in the browser:** a small wrapper (`useTurnstile`) instead of a package: the script
  loads only for guests, the widget renders with `execution: 'execute'` and
  `appearance: 'interaction-only'`, and a fresh single-use token is requested when Start is
  pressed. Local dev uses Cloudflare's invisible always-pass test keys.
- **Routing:** React Router 8 data router (`createBrowserRouter`). `/loop` is outside the main
  layout so the loop screen stays focused.
- **Loop persistence:** `sessionStorage` holds the cards and the reducer state of the current loop,
  validated with Zod on restore; it is cleared on Stop and when the loop ends (and saved again if
  Undo turns the summary back into a cycle break).
- **Button layout:** one set of buttons placed with CSS grid areas (mobile two rows, desktop one row
  under the card). Component CSS (`.btn3d`) lives in `@layer components` so Tailwind utilities win.
- **Toasts** sit above the loop button bar (mobile bottom-center, desktop bottom-right).
- **E2E:** `scripts/e2e-server.mjs` builds the SPA, seeds a separate local D1
  (`apps/api/.wrangler/e2e-state`, synthetic `seed/sample.csv` only) and runs `wrangler dev` on port
  8788 with test vars. `pnpm db:seed` gained `--persist-to`.

## D-012 · 2026-11-17 · Auth and known items (M4)

- **Better Auth** (1.7, Drizzle adapter, admin plugin) is created per request and only when needed:
  guests without a session cookie never build it. Sessions are 30 days rolling, refreshed at most
  daily; the refreshed cookie from `getSession` is passed on in the response.
- **Allow-list of Better Auth routes:** only sign-in (Google), the Google callback and sign-out
  reach Better Auth. Everything else, including the admin plugin's HTTP endpoints and
  impersonation, answers 404; admin actions will go through `/api/admin` with both locks and audit.
  The sign-in body is checked with a strict Zod schema (Google only, same-site relative callback).
- **Privacy and write budget:** OAuth state in an encrypted cookie (`storeStateStrategy: 'cookie'`),
  so starting a sign-in writes nothing; sessions store no IP or user agent; Google tokens are never
  stored (database hooks null them); `updateAccountOnSignIn: false`; telemetry off.
- **Owners:** a verified `ADMIN_EMAILS` address becomes admin at user creation, and an existing user
  is promoted at the next sign-in with one conditional `UPDATE` (writes only when the role changes).
- **Test session:** `POST /api/test/session` answers 404 unless `ENVIRONMENT=test`, and the config
  refuses `ENVIRONMENT=test` with a non-localhost `APP_URL`.
- **Known items:** one `INSERT … SELECT … FROM json_each(?) … ON CONFLICT DO NOTHING` per batch
  (idempotent, earliest mark wins, trashed/missing items skipped). The list uses keyset pagination
  (base64url cursor of sort key + item id), 50 per page, total on the first page only. Search uses
  `LIKE … ESCAPE '\'` on `normalized_text` and on translation entries via `json_each`.
- **Account deletion:** one batch deletes usage counters, the user (FK cascade: sessions, accounts,
  known items) and writes a `user.self_delete` audit row with the id only. The last active admin
  can't delete themselves (409).
- **Know queue (web):** localStorage per user (ids, target, cycle, a nonce; never text). Pending
  during the undo window, final after it or after a newer Know; debounced 2 s batches of ≤ 100;
  `keepalive` flush of everything on `pagehide`/hidden; exponential backoff; 401 pauses until the
  next start, 400 drops the batch. Undo deletes on the server when the mark may already be there
  (sent, in flight, or sent by another tab). Leaving the loop screen finalizes pending marks.
- **Follow-up for M7:** make the deployed default `ENVIRONMENT=production` in `wrangler.jsonc` and
  move the development values to `.dev.vars`, so a deploy without overrides fails closed.

## D-013 · 2026-11-17 · Admin (M5)

- **Both locks:** `requireAdmin` on the whole `/api/admin` router: DB-backed session with role
  `admin` (no session or banned → 401, other roles → 403), then, outside development/test, the
  `Cf-Access-Jwt-Assertion` JWT verified with `jose` (RS256 against the team certs, cached per
  isolate; `iss`, `aud`, expiry) and its email must equal the session email. Tested in production
  mode with real signed tokens (missing, wrong audience/issuer, expired, foreign key, email
  mismatch → 403).
- **Audit in the same batch:** every admin mutation is one D1 batch: the change, then an
  `INSERT INTO audit_log … SELECT … WHERE changes() = 1` right after it, so a change that didn't
  apply writes no audit row. (The PRD's example condition `version = :newVersion` would also match
  when _another_ edit produced that version; `changes()` doesn't have that flaw.) Category links of
  an item update are rewritten **before** the version bump, guarded by `version = :expected`, which
  can't change inside the transaction.
- **D1 change counts:** for a DELETE, D1's `meta.changes` includes rows removed by
  `ON DELETE CASCADE`, so "applied" means `changes > 0`; SQL `changes()` counts direct rows only.
- **New items** are created in one batch: insert, category links and audit find the new id through
  its identity (unique among non-deleted items).
- **Item updates** validate the merged item with the shared core rules (all known languages, so
  data of an inactive language is kept); new translations only into active languages. Only changed
  fields are written and audited (before/after). 409 `CONFLICT` details carry
  `reason: 'stale' | 'duplicate'`.
- **Preview** returns `CardView[]` for every playable active direction, built by the same
  `buildCard` as `POST /loops`.
- **Trash / cron:** the hourly cron purges up to 100 expired items per run in **one** batch
  (pairs of DELETE + conditional audit with the full snapshot, `auto: true`), deletes usage counters
  older than 48 h, and expired sessions and verifications.
- **Categories:** reorder puts the given ids first, the rest keep their order; delete is blocked
  while any item (including trashed ones, FK `RESTRICT`) uses the category. **Languages:** at
  least one stays active. **Users:** owners can't be demoted or banned, no self-demotion or
  self-ban, the last active admin can't be demoted; banning deletes every session.
- **Settings:** `PUT` takes any subset of keys (no defaults), the server validates the merged
  result (defaults active, `defaultSize` in `sizeOptions`, options ≤ `maxSize`), sorts/dedupes the
  amount choices, writes only changed keys.
- **Web:** the admin area is a lazy route (`/admin/*`, own chunk ≈ 15 KB gzip) with descendant
  routes; its strings live in `strings-admin.ts` so learners never download them. The admin client
  treats a redirect or a non-JSON 401/403 as an expired Access session and reloads `/admin`.
  "Admin" links are plain `<a href="/admin">` (full-page navigation for Access). The item editor
  serializes saves (each with the newest version); on a stale 409 it reloads the item and says so.
- **`useDebounced`** compares values by content (JSON): passing a fresh object each render no
  longer restarts its timer.

## D-014 · 2026-11-17 · CSV import UI and export (M6)

- **Import endpoint:** `POST /api/admin/import?dryRun&createMissingCategories` takes multipart
  `file`. Oversized uploads are refused from `Content-Length` before reading, and again from the
  file size (2 MB); the body is decoded as strict UTF-8 (a clear "save as CSV UTF-8" error
  otherwise). It runs the same `CsvImportService` as `pnpm db:seed`; commit is refused when the
  plan has errors; one `csv.import` audit entry holds the file name and SHA-256, never content.
- **Template:** generated by the server for the active languages, with the PRD's two illustrative
  rows, UTF-8 with BOM.
- **Import page:** Import is enabled only after a clean dry run of the same file with the same
  options (the server refuses errors anyway).
- **`pnpm db:export`:** `apps/api/scripts/export.ts`. JSON, CSV, manifest and the export README come
  from the D1 binding (`getPlatformProxy`, remote bindings for production); `sqlite/schema.sql`
  and `data.sql` come from `wrangler d1 export --no-data` / `--no-schema`. Table names are read from
  `sqlite_master` and only plain identifiers are interpolated (owner tooling, not app code). The
  export README documents every table (from `PRAGMA table_info` / `foreign_key_list`) and includes
  the PostgreSQL example. A full export refuses to write inside the content repository.
- **Zip:** a small built-in ZIP writer (Node `zlib` deflate + `crc32`), no extra dependency.
- **Throw-away databases for script tests:** `wrangler d1 export` has no `--persist-to`, so the
  scripts take `--config <copy>`: a copy of `wrangler.jsonc` in a temp folder keeps its local
  state next to it. `pnpm db:seed` gained the same option. The scripts tests (round trip,
  manifest counts, JSON shape, zip, `schema.sql` recreating every table) run in `pnpm test`.

## D-015 · 2026-11-17 · Hardening and release (M7)

- **Fail-closed configuration:** `wrangler.jsonc` vars default to `ENVIRONMENT=production` with
  placeholder values; production startup refuses to serve until Access, an https `APP_URL` etc.
  are set. Local development overrides the vars in `.dev.vars` (verified with `wrangler dev`);
  the test suites pass their full configuration explicitly (`vitest.config.ts`,
  `scripts/e2e-server.mjs`), so CI needs no `.dev.vars`.
- **Burst limits:** one Rate Limiting binding per PRD §14.3 rule (`RL_LOOPS` 10/min, `RL_AVAILABLE`
  60/min, `RL_AUTH` 20/min, `RL_IMPORT` 10/min, `RL_ADMIN` 120/min), checked before any other work.
  Keys: the hashed IP for guests, the **user id for signed-in requests** (a school or office
  network shares one IP; per-IP limits would block many learners), the admin id for admin routes.
  The test suite overrides the bindings with generous limits and tests the 429 path with a fake
  limiter (nothing is written).
- **Headers:** pages and static files get CSP + security headers from `apps/web/public/_headers`
  (Workers Assets); `/api/*` from the Worker middleware (`default-src 'none'`). The CSP is the
  PRD's, plus `object-src 'none'`, `font-src 'self'` and COOP `same-origin`; the build has no inline
  scripts or data URIs, and E2E checks there are no CSP violations. `robots.txt` allows only the
  landing and privacy pages.
- **Accessibility:** an axe scan (WCAG 2.0–2.2 A/AA, incl. contrast) of every learner and admin
  page on both viewports runs in E2E, plus a keyboard-only loop. It found one issue: the flip card's
  `aria-label` didn't contain its visible text (WCAG 2.5.3). The card's name now comes from the
  visible face; the instruction is an `aria-describedby`.
- **Logs:** unhandled errors log `{ name, method, path, requestId (cf-ray) }` only.
- **Workflows:** `deploy.yml` (push to main / manual → `production` Environment with required
  reviewer → checks → remote migrations → deploy; never seeds or exports), `codeql.yml`,
  `dependabot.yml`. Actions pinned to commit SHAs (CodeQL v4.38.3, older than two weeks).
- **Google redirect URI for local development** is `http://localhost:5173/api/auth/callback/google`
  (the Vite dev server forwards `/api` and `APP_URL` is 5173), not the 8787 URI in PRD §19.

## D-016 · 2026-11-18 · Literal meaning (owner request)

- **Why:** for idioms the meaning and the word-for-word translation are different things; keeping
  both in `translation` mixed them (the owner found such a row in the starter set).
- **Model:** a new `literal` JSON column on `items`, same shape as `translation`
  (`{ "<lang>": [entries] }`, never the item's own language, ≤ 5 entries of ≤ 200 chars), with
  matching CHECK constraints. CSV: `literal_<code>` columns (optional; old files stay valid).
  Admin: a "Literal meaning" list editor under each translation. Card: `answer.literal`, filled
  only for translation cards, rendered under the answer as "Literal meaning: …".
- **Not** used for playability, Hints, the Undo bar or "My known words" (PRD FR-L43).
- **Migration `0002_item_literal` is hand-written** (`ALTER TABLE … ADD COLUMN` with the CHECKs).
  drizzle-kit generated a table rebuild, and on D1 (foreign keys always enforced) dropping the old
  `items` table would cascade-delete known marks and category links. The drizzle snapshot is
  still updated, so `db:generate` reports no drift. Future column additions follow the same rule.
