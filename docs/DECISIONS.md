# Implementation decisions

ADR-style log of choices made while implementing [`PRD.md`](../PRD.md). Newest last.
Format: date · context · decision · consequences.

## D-001 · 2026-11-17 · Toolchain versions

- **Context:** The newest TypeScript (7.x) isn't supported by typescript-eslint yet (it requires
  `<6.1`). ESLint 9 is out of support, and `eslint-plugin-jsx-a11y` doesn't support ESLint 10.
  `@cloudflare/vitest-pool-workers` was renamed to `@cloudflare/vitest-plugin`.
- **Decision:** TypeScript `~6.0`, ESLint 10 with `eslint-plugin-jsx-a11y-x` (the maintained fork
  with ESLint 10 support), Vitest 5, `@cloudflare/vitest-plugin` (its `cloudflareTest()` Vite
  plugin; tests call the Worker through `exports.default.fetch` from `cloudflare:workers`).
- **Consequences:** Move to TypeScript 7 once typescript-eslint supports it.

## D-002 · 2026-11-17 · pnpm 12 supply-chain settings

- **Context:** pnpm 12 refuses packages published very recently (minimum release age) and blocks
  install scripts by default.
- **Decision:** Keep the default release-age protection. Instead of adding exceptions, version
  ranges allow slightly older releases. Only `esbuild` and `workerd` may run install scripts
  (`allowBuilds` in `pnpm-workspace.yaml`).
- **Consequences:** New dependencies may resolve to a version a day or two older than "latest".

## D-003 · 2026-11-17 · Local development topology

- **Context:** PRD §10.3 keeps the SPA (`apps/web`) and the Worker (`apps/api`) separate; the
  production Worker serves `../web/dist` as static assets.
- **Decision:** `pnpm dev` runs Vite on port 5173 (proxying `/api` to 8787) and `wrangler dev` on
  port 8787 in parallel, rather than using `@cloudflare/vite-plugin`. `apps/api/scripts/ensure-assets-dir.mjs`
  creates `apps/web/dist` so wrangler can start before the first build.
- **Consequences:** `APP_URL` in development is `http://localhost:5173` (the browser origin).

## D-004 · 2026-11-17 · Workspace packages are consumed as TypeScript source

- **Decision:** `@myvocab/core` and `@myvocab/contracts` export `./src/index.ts` directly; Vite and
  wrangler (esbuild) compile them. No separate build step.

## D-005 · 2026-11-17 · Generated Worker types are committed

- **Decision:** `apps/api/worker-configuration.d.ts` is generated by `pnpm --filter @myvocab/api cf-typegen`
  (`wrangler types`) and committed, so CI can typecheck without running wrangler. Re-run it after
  changing `wrangler.jsonc`.

## D-006 · 2026-11-17 · Fonts and button text color

- **Decision:** Only the Latin and Hebrew subsets of Rubik are bundled. Text on colored buttons
  uses `--on-color` (`#111014`): white text fails WCAG AA on the Know, Don't know and accent
  colors, dark text passes on all of them (≥ 4.5:1). Stop keeps light text.

## D-007 · 2026-11-17 · Scope of the no-vocabulary guard

- **Decision:** `check:no-vocabulary` checks tracked files plus untracked files that aren't
  git-ignored (so it also catches files about to be committed). Allow-listed: `seed/sample.csv`,
  `apps/api/migrations/*.sql` (schema only) and `**/fixtures/*.csv`; every allow-listed CSV is
  capped at 20 data rows.

## D-008 · 2026-11-17 · Loop engine details

- **Decision:** The loop state stores a seeded PRNG state (mulberry32), so `loopReducer` stays
  pure, tests are deterministic, and a loop restored from `sessionStorage` continues identically.
  The reducer works with item ids only; the UI looks up card content separately.
- **Undo:** the reducer keeps the most recent Know (`lastKnow`) until a new Know or Stop; the
  ~4-second Undo window is enforced by the UI timer. An undone card is appended to the next
  cycle's set; undoing after the last Know turns the summary back into a cycle break.
- **Order differs:** compared on the cards shared with the previous cycle (relative order); up to
  10 re-shuffles, then a rotation by one.

## D-009 · 2026-11-17 · CSV details

- **Decision:** Core has its own small RFC 4180 parser/serializer (no runtime dependency).
- Row numbers in import reports are spreadsheet lines (the header is line 1).
- "At least one translation or an explanation" is checked on the **merged** item (all rows of
  the same item in the file, plus the existing item), so a row may add only hints to an item
  defined elsewhere. Warnings (multiple meanings, mixed scripts) are also computed on the merged
  result, only for items the import creates or changes.
- `multiple_meanings` accepts `true/false`, `yes/no`, `1/0` (empty = false).
- List entries may not contain `|` (the CSV list separator, PRD §8.3); the shared item
  validation rejects it everywhere, which keeps the export round-trip exact.

## D-010 · 2026-11-17 · Database layer details

- **WITHOUT ROWID:** Drizzle 0.45 can't express it, so `migrations/0000_init.sql` was edited by hand
  for `item_categories`, `user_known_items` and `usage_counters`. `test/schema.test.ts` asserts it
  after all migrations run, so a future drizzle-kit table rebuild that drops it fails CI.
  When generating a new migration that rebuilds one of these tables, re-add `WITHOUT ROWID`.
- **Batches:** a D1 `batch()` counts as one query toward the per-invocation limit (50 on Free) and
  is one transaction. Drizzle's `db.batch()` can't hold raw SQL, so the import writer compiles every
  statement to `{ sql, params }` (still parameterized) and calls `D1Database.batch()` directly, up
  to 1,000 statements per batch.
- **Identity lookup:** existing items for an import are found with one query: the keys travel as
  a single JSON parameter (`json_each`) joined against `ux_items_identity`.
- **Concurrent edits during an import:** updates use the item `version`; an item that changed
  meanwhile is skipped and counted in `skippedConcurrent` (re-run the import to merge it).
- **Seeding:** `pnpm db:seed` applies local migrations, then runs the same `CsvImportService`
  through wrangler's `getPlatformProxy` (the local D1 that `wrangler dev` uses). `--remote` writes a
  temporary config with `remote: true` under `apps/api/.wrangler/tmp/` and asks for a typed
  confirmation; it needs the owner's `wrangler login`.
- **Languages** are seeded by migration `0001_seed_languages.sql` (data only).
- **Tests** reset storage and re-apply the migrations before every test.
